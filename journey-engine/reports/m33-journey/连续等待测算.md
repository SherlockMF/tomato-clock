## 判定口径

同一人物紧挨着的 waiting 分钟合成一段，跨专注窗或跨午夜继续累计。吃饭、移动、办事等实际行动和睡眠的日历间隔都能打断等待。零时长标记不切断等待。观察截止时仍在等的，只算已过去的分钟。P95 按所有观测段合并后的最近秩计算，每段权重相同。各阈值含等号，达到阈值就计入整段分钟。分档互相包含，不能相加。

## 规则和假设

- 新预设允许在有厨房、营业、路费、食材费和时间的地点备两份路餐。一批耗时 30 分钟，实际支付 8 元。两份吃完前不能再次备餐。吃路餐同样占用用餐时间。
- 没有可执行行程时，已在现场的人可以接手闲置至少一小时的公共事务。原负责人已经出发、已预订该事务、有进度或物品已经有人携带时，保留原安排。每项公共事务最多转交一次。
- 连续等满一小时后，可将已经有实际需要的洗护和活动身体提前。使用洗护用品和锻炼后的冷却仍然有效。
- 旧存档继续按原规则运行。打开旅途的“体验停滞”页，即可看到对应样本的等待段数、中位数、P95、最大值及 30、60、120、180、240 分钟的累计段数与分钟数。

## 文件及复现

等待统计在 `src/journey/waits.ts`，调度和库存改动在 `src/journey/{world,world-types,provisions,attributes}.ts` 与 `src/life32r3/{city,engine,itinerary,planner,state,types}.ts`。诊断和试玩接入在 `src/life32r3/diagnostics.ts`、`src/studio/life32r3-{catalog,routes}.ts` 和 `studio/life32r3.js`。回归用例在 `tests/journey-waits.test.ts`、`tests/journey-runtime.test.ts` 和 `tests/studio/journey.test.ts`。

```powershell
node scripts/journey-eval.ts 30 19
node scripts/journey-eval.ts 30 41
node scripts/journey-eval.ts 30 73
node scripts/journey-eval.ts 100 19 creator
node scripts/journey-eval.ts 365 41 low_assets
```

每条命令添加 `--previous` 可复现上一版。完整分钟分布和逐条轨迹见[连续等待测算数据](wait-episodes.json)。`npm run check` 通过，含 292 项测试。另有 35 项边界测试通过。试玩存档 39 窗经 SQLite 回放，浏览器显示的 20 段、合计 565 分钟、最长 65 分钟与指标接口一致。
